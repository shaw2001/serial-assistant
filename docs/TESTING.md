# 验证与实体验收

## 自动验证

- `npm test`：原始 00–FF 字节、UTF-8 / GBK 拆包、CRLF、ASCII、HEX 校验；四设备隔离；发送失败不计 TX；队列取消与顺序；忙时周期跳过；100 次连接关闭；磁盘记录、缓存与写入失败；配置损坏恢复；界面异步发送目标、设备草稿、暂停、搜索转义和历史去重。
- `npm run test:pty`：Linux 内核的两个真实 PTY，使用生产 serialport 库而非 Mock；双向 00–FF、拆分中文、周期隔离、原始导出、十次重连、拔出隔离。
- Windows Release 流水线：所有 JS 测试、原生 binding 加载与系统枚举、真实 Electron 窗口启动及 preload IPC 初始化、NSIS / ZIP 构建、EXE 版本资源检查、包结构和校验文件。

PTY 测试不是物理 USB 串口测试。CI 桌面启动检查不是人工视觉或 Windows 实体设备验收；没有声称完成 8 小时连续负载、睡眠唤醒、所有驱动及 DPI 组合验证。

## Windows 实体设备检查

1. 安装对应适配器驱动。在 Windows 10 / 11 x64 解压并运行，检查字体、浅色、100% / 150% DPI、小窗口布局。
2. 使用两组互通或回环适配器，115200 / 8N1。发送 `00 01 0A 0D 7F 80 FE FF`，查看 HEX RX 与导出的 Base64 原始值。
3. 各设备分别发送 UTF-8 和 GBK 中文，接收编码设为对应格式。设置自定义 250000；确认实际驱动接受或明确报错。
4. 打开四个独立端口，切换时验证草稿、RX/TX、周期参数和命令目标。尝试占用端口，错误应可读且其他设备继续。
5. 周期发送时拔出一个设备；该会话停止，其他会话继续。重新插入后手动连接，不回放旧发送队列。
6. 暂停显示后持续接收，RX 增长且恢复可见；清空显示后完整记录仍可导出。
7. 新增指令、配置导出、重启恢复和配置导入；确认不会自动连接或发送。
8. 导出 TXT / JSON / JSONL 并核对方向、主机时间、字节计数。测试磁盘不可写、设备拔出及系统睡眠恢复；保留具体驱动与系统信息。
9. 对目标最大波特率连续运行 8 小时，检查内存、缓存裁剪、分段日志、统计及记录缺失提示。不要仅凭 UI 行数判断字节无损。
